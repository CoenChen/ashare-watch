# A 股实时行情 · 本地仪表盘

> **直接从公开行情接口抓数据，在你自己电脑上跑一个 A 股实时看板。**
> 零第三方依赖，双击一个 `start.bat` 就能用；也可以导出成单文件 HTML 离线看或发给别人。

![A 股看板预览](docs/preview.png)

---

## 30 秒上手

**第一步：确认有 Python。** 装了 Anaconda 就有；没有的话去
<https://www.python.org/downloads/> 下载，安装时记得勾选 `Add python.exe to PATH`。

**第二步：双击 `start.bat`。**

浏览器会自动打开 `http://127.0.0.1:8771`，数据自动抓取并持续刷新。
关闭那个黑窗口就是停止服务。

> **不需要 pip install，不需要 API Key，不需要注册任何账号。**
> 整个项目只用 Python 标准库。

> **端口说明**：这个看板用 **8771**，和之前那个美股看板（8770）不冲突，可以同时开着。

## 想发微信分享给别人？

**关键前提：微信能打开的是「链接」，不是「文件」。**
手机微信收到 `.html` 文件点了会提示「暂不支持打开该类型文件」。
所以要让人在手机上看到，得有一个公网链接。

项目已经为此准备好了两样东西：

* `docs/index.html` —— 一个约 400KB 的**单文件看板**（样式、脚本、数据、
  全市场搜索索引全内联），丢到任何静态托管上就是一个能发微信的链接；
* `.github/workflows/pages.yml` —— 每个交易日自动重新抓取并更新它。

只需要三步：推到 GitHub（**Public** 仓库）→ 仓库 **Settings → Pages**，
**Source 选 `GitHub Actions`** → 在 Actions 标签页手动跑一次工作流，
拿到 `https://<用户名>.github.io/ashare-watch/` 这个链接发出去。

> **注意 Source 要选 `GitHub Actions`，不是 `Deploy from a branch`。**
> 早期版本是让工作流把快照提交回 `main` 分支再发布，结果**必然和本地开发冲突**
> （工作流写 main、你本地也写 main，两边一定分叉，推送会被拒绝）。
> 现在改成官方 artifact 部署：工作流只读仓库，不碰任何分支。

完整的三种方案对比（Pages 链接 / 内网穿透实时 / 直接发图）、
国内访问速度的真实情况、以及不想公开代码时的绕法，
都写在 **[docs/06_微信分享指南.md](docs/06_微信分享指南.md)**。

> 分享出去的页面顶部会有一条明确提示：「这是 X 时刻的行情快照，不会自动更新」，
> 数据超过 1 小时后会变成橙色警示。**这是刻意加的**——别人点开链接时很容易
> 把快照当成实时行情，那会误导判断。

### 两个必须做对的地方

**红涨绿跌。** 中国股市和美股相反：红色是涨、绿色是跌。
如果照搬美股配色，每一根 K 线都会被读反。这个项目的配色由 CSS 变量
`--up` / `--down` 统一定义，并且有测试守护（`test_store_render.py` 里
`test_standalone_html_uses_red_for_gain`），防止哪天被改回去。

**涨跌停要分板块。** 主板 ±10%、创业板与科创板 ±20%、北交所 ±30%，
主板 ST 股 ±5%。判断"是否涨停"必须先知道这只股票属于哪个板，
而且要考虑交易所的涨跌停价四舍五入到分——实际涨幅常常是 9.97% 或 20.02%，
不能用等号判断。这些规则集中在 `market.py` 里。

### 环球市场为什么按这十类分

A 股不是孤立的，外部变量通过不同路径传导进来，所以面板按传导链条分了组：

| 分组 | 品种 | 对 A 股的传导路径 |
|---|---|---|
| 贵金属 | 伦敦金／银、纽约黄金／白银、伦敦铂金、伦敦钯金（6） | 避险情绪、实际利率、黄金与有色板块 |
| 国内贵金属 | 沪金主力、沪银主力 | 山东黄金、中金黄金这类标的跟的是**国内金价**，不是伦敦金 |
| 能源 | WTI、布伦特、天然气、原油 SC | 石油石化盈利、航空与化工成本 |
| 基本金属 | 伦铜／铝／锌／镍、沪铜／沪铝主力 | 有色板块、制造业需求预期 |
| 黑色系 | 螺纹钢、铁矿石、焦煤、焦炭 | 地产、基建、钢铁与煤炭股的景气度 |
| 化工 | PTA、甲醇、纯碱 | 化纤、煤化工、纯碱玻璃这条链 |
| 农产品 | 豆粕、郑棉、白糖 | 食品饲料、纺织服装的成本端 |
| 海外股指 | 标普 500／纳指 100／道指／恒指／富时 A50 期货 | 隔夜外盘是 A 股开盘前最直接的情绪参考 |
| 外汇 | 美元指数、在岸与离岸人民币、主要货币对、新兴市场货币、人民币交叉盘（22） | 外资流向、出口链、美元流动性 |
| 数字货币 | 比特币 | 全球风险偏好的温度计 |

**分组标题可以点，点一下就收起来，收起状态存在浏览器里。** 右上角还有一个
「全部收起 / 全部展开」的一键开关——56 个品种全展开有将近 1800px 高，
不看的组收起来，页面就不会被它占满。

**手机上第一次打开会默认全部收起。** 桌面屏幕宽，默认展开；但窄屏上 56 个品种
铺开有七八千像素高，一路往下拉很劝退。10 个分组标题加起来还不到一屏，
先收着、想看哪组再点开更合理。手动点过之后就以你的选择为准。

**几个格式细节**（都写在 `structure.py` 的注释里）：

- 这些品种在新浪接口里用了**四套完全不同的字段布局**，而且都是按下标取的，
  所以必须逐套解析、逐套写测试。最容易踩的是国内期货：第 5 位叫「昨收盘」，
  但期货没有收盘价、这一位恒为 `0.000`，真正的基准是第 10 位「昨结算」——
  用错位置，沪金的涨跌会从 +1% 变成 −0.3%，而且页面上完全看不出异常；
- 品种多了以后，`list=` 拼出来的 URL 会变长，所以请求按 **40 个一批**拆分并发取，
  而不是赌一条超长 URL 不会被截断；
- 外盘期货和美元指数**只给昨收价**，涨跌幅要自己算；外汇接口则直接给了涨跌幅，
  用它的更准；
- **小数位按量级决定**：美元人民币是 6.7066（要 4 位才看得出变化），
  黄金是 4,362.98（2 位就够）。统一格式会让汇率看起来像一潭死水；
- 每个品种都标了**计价单位**（美元/盎司、美元/桶、美元/吨），
  否则单看数字判断不了量级是否正常。

### 刷新频率：为什么是 15 秒，而不是 3 秒

先说结论：**15 秒是实测出来的甜点，5 秒是可行下限，3 秒做不到也不划算。**

先算一笔账。一次完整采集约发 59 个请求，其中：

| 部分 | 请求数 | 刷新方式 |
|---|---|---|
| 指数 + 自选股（批量） | 1 | 每个刷新周期 |
| 环球市场 | 2（56 个品种，按 40 个一批拆） | 每个刷新周期 |
| 行业板块 | 1 | 按缓存（默认 5 分钟） |
| **全市场分页** | **56** | 按缓存（默认 4 分钟） |

**全市场那 56 页占了 95% 的请求量**，而它是按缓存刷新的，跟界面刷新频率无关。
所以把界面刷新从 60 秒提到 15 秒，多出来的请求是有限的：

| 配置 | 请求量 | 相对现在的倍数 |
|---|---|---|
| 60 秒 + 全市场缓存 180 秒 | 21.9 请求/分钟 | 1.0× |
| **15 秒 + 全市场缓存 240 秒（当前）** | **26.2 请求/分钟** | **1.2×** |
| 5 秒 | 54.9 请求/分钟 | 2.5× |
| 3 秒 | 78.9 请求/分钟 | 3.6× |

**刷新快 4 倍，请求量只多两成。**

那为什么不做 3 秒？三个理由：

1. **技术上做不到**。一次完整采集（含全市场 56 页）实测 6.4 秒，
   3 秒的间隔会让请求重叠堆积。代码里为此设了 2 秒的硬下限
   （`min_refresh_seconds`）。
2. **数据源没那么快**。A 股交易所的 Level-1 行情本身是 3 秒一档，
   而网页接口返回的数据刷新频率更低。刷得再快，数据没变就是没变。
3. **会被限流**。我们用的是公开网页接口，不是授权数据源。
   实测中已经撞到过新浪的 HTTP 456 限流响应。持续高频访问有被封的风险。

> 那些"3 秒一刷"的行情 App，背后接的是**交易所授权的 Level-1/Level-2 推送**
> （付费、走专线），和抓网页接口完全不是一回事。这是本质区别，
> 不是配置问题。

想自己调，改 `.env` 里的 `ASHARE_WATCH_REFRESH_SECONDS` 即可。

### 搜索是怎么做的

**纯本地过滤，不发任何请求。** 服务端把全市场 5500+ 只压成一个精简数组
（字段顺序固定：`[代码, 名称, 现价, 涨跌幅, 换手率, 成交额]`），
前端加载一次后在本地匹配，5500 条数组过滤是微秒级的。

几个实现取舍：

- **用数组而不是对象**存索引：对象写法要 500KB+，数组只要 213KB。
- **索引不放进快照**：快照每 15 秒被序列化一次、还要存 500 份进 SQLite，
  塞进 200 多 KB 的索引会让数据库膨胀到上百 MB。所以它单独成一个接口
  `/api/search-index`，前端 5 分钟取一次。
- **匹配打分**：代码精确 > 代码前缀 > 名称前缀 > 代码包含 > 名称包含，
  同分时按成交额排。所以输入「688」先出成交额最大的科创板股票。
- 静态分享页面里**搜索同样可用**——索引被内联进了单文件 HTML。

### 我的关注是怎么做的

搜索到想看的股票，点结果右侧的 **☆** 就加进「我的关注」面板；面板里每张卡
右上的 **×** 移除，右上角的「全部清空」点一次变成「再点一次确认」，
再点一次才真的清空（不弹浏览器原生弹窗，免得样式和页面不搭）。

**关注列表存在浏览器本地（localStorage），不经过服务端。** 三个理由：

1. **静态分享页没有服务端**。别人打开你发的那份单文件 HTML，搜索和关注照样能用；
2. **不需要账号体系**。关注是个人偏好，为它引入登录、数据库、隐私声明不划算；
3. **不需要改配置重启**。加了哪只股票，刷新页面还在。

行情数据走两条路：

| 场景 | 数据来源 | 时效 |
|---|---|---|
| 本地服务 | `GET /api/quotes?codes=...`（和自选股同一个节奏，20 秒一次） | 实时 |
| 静态分享页 | 内联的全市场搜索索引 | 滞后几分钟，但离线可用 |

接口有 **60 个代码的上限**，避免有人拿它当批量下载用；关注上限是 30 只。

还有一个细节：**上一次看到的行情也一起存了下来**。刷新页面时先用它把卡片画出来，
接口回来再覆盖——否则刚打开的一瞬间会是一屏「—」，看着像坏了。
万一某只股票连缓存都没有，卡片会显示「正在取行情…」的虚线占位，而不是摆一个空值。

### 点进一只股票看什么（按需抓取）

**结论：点开的时候再去抓完全来得及，不需要为了详情把全市场都爬一遍。**

全市场 5500 多只，如果每只都预先抓一份 K 线，那就是 5500 多个请求——又慢，
几乎必然被接口限流。而单只股票只有 4 个请求、**实测 0.6 秒左右**就回来了，
用户点开的瞬间去抓是最划算的做法。

点开后会展开一个侧栏，里面有：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 关键指标 | 今开／昨收／最高／最低、成交量、成交额、换手率、振幅、市盈率、市净率、总市值、流通市值 | 实时行情 + 全市场索引 |
| 分时走势 | 最近一个交易日的 5 分钟线，带昨收虚线 | K 线接口 |
| 日线 | 近 120 个交易日 | K 线接口 |
| 买卖五档 | 买一～买五、卖一～卖五的价格和挂单量 | **实时行情里本来就带着，零额外请求** |
| 资金流向 | 最近 5 个交易日的主力净额与涨跌幅 | 资金流向接口 |

两个实现上的取舍：

- **五档不额外请求。** 新浪的个股行情字段里第 10–29 位本来就是五档，以前只是丢掉了。
  解析规则写在 `structure.orderbook_fields`，指数没有这一段，会返回空。
- **市盈率／市净率／市值不额外请求。** 它们只存在于全市场接口，而那份数据每 4 分钟
  本来就要抓一次，于是顺手写进了搜索索引（多了 4 个字段、几十 KB），
  点开时直接读本地，静态分享页上也能看到。

详情接口 `/api/stock?code=600519` 只在本地服务里存在，代码格式在入口就卡死
（只接受 6 位数字，可带 sh/sz/bj 前缀），因为它会被拼进上游请求路径。
**静态分享页没有后端**，点开只会显示能拿到的部分：

* 自选股和四个榜单里的那几十只——完整行情都在快照里，12 个指标都能显示；
* 其余 5000 多只——显示索引里带的成交额、换手率、市盈率、市净率、市值；
* 分时、K 线、五档、资金流向需要实时抓取，单文件网页带不动，会明确说明「要在本机跑服务」。

不管哪条路，**不会摆一排「—」出来**——没有的数据就不显示那一格。

## 数据是从哪来的

全部是公开行情接口，且都经过实测验证：

| 用途 | 接口 |
|---|---|
| 指数与个股行情 | `hq.sinajs.cn/list=...`（批量，GBK） |
| 全市场分页快照 | `Market_Center.getHQNodeData` |
| 全市场股票数量 | `Market_Center.getHQNodeStockCount` |
| 行业板块 | `newSinaHy.php`（官方行业分类） |
| 指数日线 | `CN_MarketDataService.getKLineData` |

另外也验证过**上交所与深交所官网接口**（`query.sse.com.cn`、`www.szse.cn/api`）
可以正常访问，它们更适合做单市场深度数据，本项目当前没有使用。

几个实现细节值得说明，因为它们决定了"能不能稳定跑"：

**连接复用是性能关键。** 全市场要翻 56 页。如果每次请求都新建连接，
TLS 握手会把整个采集拖到一分钟以上。改成每个工作线程按域名持有一条长连接后，
**完整采集（5563 只 + 5 个指数 + 49 个板块 + 日线）只要 3.7 秒**。

**一次抓全市场，本地算榜单。** 涨跌幅榜、市场宽度、涨跌停统计这三个视图
共用同一份全市场快照。接口本身支持按字段排序，所以不需要本地排序，
也不需要逐只股票去查。

**交易时段用北京时间算，但不读本机时区。** A 股没有夏令时，
按 UTC+8 换算即可；用 UTC 换算而不是读本机时区，换台电脑也不会算错。
节假日通过"行情数据里的日期不是今天"来识别。

**抓取失败不会让页面白屏。** 任何一个数据源失败都会记进 `warnings`，
页面上明确提示哪部分可能不是最新的，而不是悄悄显示空白。

## 两种使用形态

### 形态一：本地服务（日常用这个）

```bash
python scripts/serve.py
```

刷新节奏自动切换：

* **盘中**（9:30–11:30、13:00–15:00）：每 15 秒抓一次
* **其他时间**：每 15 分钟抓一次

重复双击 `start.bat` 不会启动出第二份：服务发现端口上已经有一个看板在跑，
会直接把已有的那个打开，并告诉你「已经在运行了」。
（Windows 上如果允许端口复用，两个进程会同时绑同一个端口、老的继续收请求，
表现就是「改了代码、重启了、页面还是旧数据」——这个坑已经堵上了。）

### 形态二：单文件 HTML 快照（分享或离线用）

```bash
python scripts/export_html.py --refresh
```

生成 `data/exports/ashare-dashboard.html`，样式、脚本、数据全部内联。
双击就能打开，不需要联网、不需要 Python，可以直接发给别人。
页面里也有一键导出按钮。

## 让它每天自动更新

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1
```

默认在 A 股交易时段的六个时间点自动抓取并导出快照（北京时间）：
`09:35`、`10:30`、`11:25`、`13:05`、`14:00`、`14:55`。
这样即使你整天没开服务，随时双击 HTML 也能看到最近一次的数据。

删除任务：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1 -Uninstall
```

## 自定义

复制 `.env.example` 为 `.env` 后修改（或直接改环境变量）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ASHARE_WATCH_SYMBOLS` | 20 只行业龙头 | 自选股，6 位代码逗号分隔 |
| `ASHARE_WATCH_REFRESH_SECONDS` | `15` | 盘中刷新间隔（硬下限 2 秒） |
| `ASHARE_WATCH_IDLE_SECONDS` | `900` | 非交易时段刷新间隔 |
| `ASHARE_WATCH_UNIVERSE_TTL` | `240` | 全市场快照缓存时间（抓一次要翻 56 页，别设太小） |
| `ASHARE_WATCH_WORKERS` | `8` | 并发请求数（调大容易撞新浪的 HTTP 456 限流） |
| `ASHARE_WATCH_PORT` | `8771` | 服务端口 |
| `ASHARE_WATCH_NO_BROWSER` | 未设置 | 设成 `1` 则启动后不自动打开浏览器 |

只想看几只股票：

```bash
set ASHARE_WATCH_SYMBOLS=600519,300750,000858
python scripts\serve.py
```

```
ashare-watch/
├── start.bat                     Windows 双击启动

│   ├── config.py                 配置（环境变量覆盖）
│   ├── models.py                 数据结构

│   ├── collector.py              采集编排
│   ├── store.py                  SQLite：快照历史 + 采集日志
│   ├── render.py                 导出单文件 HTML
│   ├── server.py                 零依赖 HTTP 服务 + 后台定时刷新

└── docs/                         可分享的单文件页面（也是抓取失败时的兜底）
```

## 测试

```bash
pip install -e ".[dev]"
pytest -q
```

113 个测试，覆盖：

* **启动脚本的格式约束**：CRLF 换行、纯 ASCII、候选解释器必须真的执行过、
  结尾必须有 pause（这几条都来自真实故障，见下）
* **A 股交易规则**：午间休市识别、板块判定、涨跌停幅度、一字板、
  涨跌停价的容差处理
* **代码到市场的映射**：`sh000001` 是指数而 `sz000001` 是股票，
  `920xxx` 属于北交所而不是沪市
* 榜单排序、停牌与新股过滤、市场宽度、炸板统计
* 数据源解析（用真实响应片段，离线可跑），**四套环球市场字段布局各锁一遍**，
  包括国内期货必须取「昨结算」而不是「今日最高」
* 环球市场的分批请求：每一批的 `list=` 都不能太长，多批结果要合并且保持顺序
* 个股详情：五档盘口按位置解析（买一价必须低于卖一价）、指数不带五档、
  代码格式的入口校验、抓不到数据时返回空结构而不是抛异常
* 单文件 HTML 的内联完整性与 `</script>` 转义；**内联的 JS/CSS 必须和源文件
  逐字节一致**（`re.sub` 的替换串会把 `\d` 当转义处理，这个坑踩过一次）
* HTTP 接口：参数解析、60 个代码的上限、**同一端口不允许启动第二份看板**
* 前端静态检查：关注列表的初始化顺序、`$("id")` 是否都真实存在、
  **HTML 注释必须闭合**（写成 `*/` 会把整段标记吞掉，元素在文件里"存在"、
  在浏览器里却是 null）
* **红涨绿跌的配色守护**

## 启动失败 / 窗口一闪就没了

先绕过批处理，直接在文件夹里按住 `Shift` 右键选「在此处打开 PowerShell 窗口」，
执行：

```bash
python scripts\serve.py
```

这样能看到完整错误。常见情况：

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示 `Python was not found; ... Microsoft Store` | **Windows 自带的假 python.exe**（App Execution Alias），不是真的 Python | 见下 |
| 提示 `python 不是内部或外部命令` | Python 没装或没加进 PATH | 重装并勾选 `Add python.exe to PATH` |
| 提示端口被占用 | 8771 已被占用 | 关掉旧窗口，或 `set ASHARE_WATCH_PORT=8772` |
| 提示 `ModuleNotFoundError` | 在错误的目录下执行 | 先 `cd /d D:\codex\ashare-watch` |

### 关于微软商店的假 Python

Windows 默认在 `AppData\Local\Microsoft\WindowsApps\` 下放了一个 `python.exe`，
它**看起来是 Python，其实只是个跳转链接**：不带参数运行打开微软商店，
带参数运行直接报错退出（退出码 9009）。麻烦的是它在 PATH 最前面，
会把真正的 Python 盖住。

`start.bat` 已经能自动跳过它：脚本会**逐个候选真的执行一次**，
哪个能跑通才用哪个（见 `tests/test_launcher.py` 的守护测试）。
想彻底关掉这个别名：**设置 → 应用 → 高级应用设置 → 应用执行别名**。

## 已知限制

1. **用的是公开行情接口，不是官方授权数据。** 接口随时可能调整字段或加限制。
   所有解析都集中在 `structure.py` 与 `client.py`，改起来只动一处。
2. **行情可能有延迟。** 免费接口的部分数据不是逐笔实时，不适合做交易决策依据。
3. **全市场快照有 4 分钟缓存。** 榜单、宽度、涨跌停统计因此最多滞后 4 分钟；
   指数、自选股和「我的关注」是实时的。这个缓存是为了避免每次刷新都翻 56 页。
4. **节假日靠数据日期推断。** 没有内置交易日历，休市日会显示"已收盘"并
   标注最近交易日。要精确判断需要接一个交易日历。
5. **没有做历史存档的深度分析。** SQLite 里存了快照，目前只用于"重启后立刻有内容"
   和采集日志，还没有做走势回顾、异动回放。

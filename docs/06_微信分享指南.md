# 通过微信分享给他人

## 先说清楚一个前提：微信能打开的是「链接」，不是「文件」

这是决定方案的关键，很多人第一次会踩：

| 你发的东西 | 手机微信里点开的结果 |
|---|---|
| `.html` 文件 | ❌ 提示「暂不支持打开该类型文件」，只能转发 |
| 一张图片 | ✅ 正常查看，还能收藏、转发 |
| 一个 **公网链接** | ✅ 用微信内置浏览器打开，完整体验 |

所以想让人在手机微信里看到你的看板，**必须有一个公网链接**。
（PC 版微信收到 `.html` 文件倒是可以用浏览器打开，但对方多半在手机上。）

下面按推荐顺序给三种方案。

---

## 方案 A：GitHub Pages（推荐，一次配置长期有效）

项目已经准备好了：`docs/index.html` 就是完整的单文件看板，
`.github/workflows/pages.yml` 会定时重新抓取并更新它。

### 步骤 1：把项目推到 GitHub

```bash
cd /d D:\codex\ashare-watch
git remote add origin https://github.com/<你的用户名>/ashare-watch.git
git branch -M main
git push -u origin main
```

### 步骤 2：开启 Pages

1. 打开仓库页面 → 上方 **Settings**
2. 左侧栏找到 **Pages**
3. **Source** 选 **`GitHub Actions`**
   （**不是** `Deploy from a branch`——见下方说明）
4. 回到 **Actions** 标签页，选 **更新行情快照并发布到 Pages** → **Run workflow**，
   手动跑一次

大约 1 分钟后，页面顶部会出现你的链接：

```
https://<你的用户名>.github.io/ashare-watch/
```

**在手机上打开这个链接确认一下**，然后在微信里直接发出去就行。

> 免费账号要求仓库是 **Public**。如果不想公开代码，见文末「不想公开代码怎么办」。

> **为什么必须选 GitHub Actions？**
> 项目最初的做法是让工作流把快照提交回 `main` 分支，再用
> `Deploy from a branch /docs` 发布。但它有个必然的副作用：
> **工作流每隔几小时往 `main` 写一个提交，本地开发也往 `main` 写提交，
> 两边一定会分叉**。实测确实撞上了——远程攒了几个快照提交之后，
> 本地推送直接被拒绝，表现为「点了推送，GitHub 上却没有变化」。
>
> 一个分支只能有一个写者。现在改成官方推荐的 artifact 部署：
> 工作流只读仓库，在 CI 里构建后直接发布，不碰任何分支，
> 从根上消除了这个冲突。

### 步骤 3（可选但强烈建议）：让链接自动更新

默认情况下，`docs/index.html` 是你本地构建的那一份快照，数据会一直停在那里。
想让链接每隔几小时自动刷新，开启 Actions 写权限即可：

1. **Settings → Actions → General**
2. 拉到最下面 **Workflow permissions**，选 **Read and write permissions**，Save

之后 `pages.yml` 会在每个交易日自动跑五次（北京时间约 09:40、11:50、13:10、14:45、15:30），
重新抓取行情并更新 `docs/index.html`。也可以随时在 **Actions** 标签页手动点一次 **Run workflow**。

> **抓取失败会怎样？** 工作流会跳过提交，线上保留上一次的快照，
> 不会把页面变成空白。这是刻意设计的——宁可数据旧一点，也不要打开是白屏。

## 方案 B：内网穿透（想要「真正的实时数据」）

Pages 方案的数据是定时快照。如果你希望别人点开看到的是**此刻的实时行情**，
可以用内网穿透把本地服务暴露到公网。

需要先装 [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)，
然后：

```bash
# 1. 本地服务开着
python scripts\serve.py

# 2. 另开一个窗口，把本地端口暴露出去
cloudflared tunnel --url http://127.0.0.1:8771
```

命令会输出一个形如 `https://xxxx-xxxx.trycloudflare.com` 的链接，
**这个链接在微信里可以直接打开，而且是实时的**。

**代价（要说清楚）：**

- 你的电脑必须一直开着，关掉窗口链接立刻失效
- 链接是一次性的，每次重启都会变
- 免费版没有稳定性保证，偶尔会断

所以这个方案适合「我现在就想让朋友看一眼实时盘面」，不适合长期挂在群里。

---

## 方案 C：直接发图（最省事，微信原生体验最好）

如果只是想让对方**看一眼今天的盘面**，发图片其实是最优解：
不会打不开、不用等加载、可以收藏。

在浏览器里打开看板，用手机或电脑截图即可。
电脑上想截整页长图：Chrome 按 `F12` 打开开发者工具 →
`Ctrl+Shift+P` → 输入 `screenshot` → 选 **Capture full size screenshot**。

仓库里的 `docs/preview-mobile.png` 就是手机尺寸的效果参考。

---

## 三种方案怎么选

| 场景 | 推荐 |
|---|---|
| 想长期挂在群里、别人随时能点开 | **方案 A**（GitHub Pages） |
| 想让朋友现在就看到实时行情 | **方案 B**（内网穿透） |
| 只想让对方看一眼今天的盘面 | **方案 C**（发图） |
| 既要长期、又要实时 | A + B 一起：A 做常驻入口，B 临时分享 |

## 关于国内访问速度（说实话）

`github.io` 在国内的访问**时快时慢，偶尔会打不开**——这不是项目的问题，
是 GitHub 本身的网络状况。如果对方打不开，可以换：

| 托管 | 国内速度 | 成本 | 说明 |
|---|---|---|---|
| GitHub Pages | 不稳定 | 免费 | 最省事，配置最少 |
| Cloudflare Pages | 较好 | 免费 | 连 GitHub 仓库自动构建，同样免费 |
| Gitee Pages | 快 | 需实名 + 开通服务 | 国内访问最接近「秒开」 |
| 腾讯云 COS / 阿里云 OSS 静态网站 | 最快 | 几块钱/月 | 用自己的域名需要备案 |

换托管不需要改项目：把 `docs/` 目录整个传上去就行，它就是一个纯静态站点。

## 打开链接的人会看到什么

页面顶部会有一条明确的提示：

> 这是 2026-09-16 23:01:28 的行情快照（3 分钟前生成）。
> 本页为静态页面，**不会自动更新**——想看实时行情请在本机运行项目。

数据超过 1 小时后，这条提示会变成醒目的橙色，写明「数据可能已过期」。

**为什么一定要加这条？** 因为别人点开链接时，很容易把快照当成实时行情去判断，
那会误导人。宁可把话说在前面。

---

## 不想公开代码怎么办

免费账号的 GitHub Pages 只能用于 Public 仓库。三种绕法：

1. **开一个专门的分享仓库**（推荐）：只放 `docs/` 里的那一个 HTML 文件，代码仓库保持 Private。
2. **用 Cloudflare Pages**：可以连私有仓库，免费额度够用。
3. **把 HTML 传到任意对象存储**（腾讯云 COS 等），开静态网站访问。
